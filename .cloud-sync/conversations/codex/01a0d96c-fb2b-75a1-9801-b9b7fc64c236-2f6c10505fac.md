**Q9.1: When a question is too long to fit, what should give first?**

Here's what I recommend, in this order:
1. **Shrink the header, breadcrumb and toolbar.** Every question gets that space back, and nothing a student reads gets smaller.
2. **Size the text to each question**, but never below a 15px floor. A median question (1,041 characters) should then fit at 1536×695 with the text barely smaller than today.
3. **Only the longest questions scroll**, like PT114-S2-Q23 at 2,412 characters. Those scroll inside their own column, the way RC does. The page itself never scrolls, so the toolbar and the next/submit controls stay on screen.

The tradeoff: with step 2, text size changes a little from one question to the next. The other way is to keep one size for everything and let long questions scroll. The text stays steady, but more questions end up with a scrollbar.

Do you want text sized per question with the 15px floor, or one fixed size with more questions scrolling?

## Risks of sizing text per question

- **It can fight a student's own text-size setting.** The Question screen already has a text-size control. If auto-fit overrides it, a student who chose larger text gets it shrunk. That's the most serious risk, and it can be avoided, but only if the build gets it right.
- **Flicker.** To fit the text, the page has to measure it after it appears. Students could see text jump from one size to another as a question loads, or when fonts load late.
- **It's less like the real test.** On LawHub the text stays one size. A student practising with sizes that shift from question to question is practising on something the test won't give them.
- **More code, more ways to break.** Measuring and resizing is the fiddly kind of code that breaks on screen sizes nobody tested.

## Risks of one fixed size with scrolling

- **A student could miss choice E.** This is the bug you reported in the first place. If the choices column has to scroll, E can sit just out of sight. The fix is a clear cue, like a fade and a "more below" hint, so nobody thinks there are only four choices.
- **Scrolling in two columns can confuse at first.** The mouse wheel scrolls whichever column the pointer is over. RC already works this way, so students have seen it, but it's still a small change for LR.
- **Long questions still need a scroll.** Only the long ones, though. Once the header is shrunk, most questions should fit.

## My recommendation has changed

I recommended per-question sizing before. With your worry in mind, I now recommend **one fixed size with scrolling**:
- Shrink the header, breadcrumb and toolbar.
- Keep the text at the size the student chose.
- Let each column scroll on its own, like RC and like LawHub, with a clear cue whenever a choice is out of sight.

It has fewer moving parts, it can't override a student's setting, and it matches the real test. Its one serious risk, a hidden choice E, has a simple fix I can check at every screen size.
