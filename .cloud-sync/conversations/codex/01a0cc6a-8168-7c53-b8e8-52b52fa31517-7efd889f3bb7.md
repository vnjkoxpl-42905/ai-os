Across the docs, this is called the built-in backend (Cloud), as opposed to an external backend you connect yourself, such as \ue200cite\ue20244†Supabase\ue201 .\nL125: ##\nL126: \nL127: \ue200cite\ue20245†\u200b\ue201 L128: \nL129: Why use the built-in backend\nL130: \nL131: Three things make it the default choice for most projects:\nL132:   * Scales as you grow: From your first prototype to millions of users, Lovable scales seamlessly with your needs.\nL133:   * Secure by default: Enterprise-grade authentication, fine-grained access controls, and compliance best practices protect your app and data.\nL134:   * Cost-effective: Manage multiple projects in one workspace with credit-based usage. Lovable includes monthly Cloud grants on Free, Pro, and Business plans. \nL117: Backend (Cloud)\nL118: # Advanced settings\nL119: \nL120: Manage the infrastructure behind your app’s built-in backend (Cloud): check its resource health, resize it, increase database storage, export your data, and pause or remove it.\nL121: \nL122: Copy page Copy page\nL123: \nL124: Advanced settings is where you manage the infrastructure behind a project’s built-in backend (Cloud): its resource health, instance size, and database storage, plus data exports, pausing, and removal. To open it, go to More → Cloud → Overview → Advanced settings.\nL125: ##\nL126: \nL127: \ue200cite\ue20244†\u200b\ue201 L128: \nL129: Check your database’s resource health\nL130: On all plans, Advanced settings opens with three cards: CPU, Memory, and Disk. Each card shows the last 24 hours as a row of hourly segments. Lovable highlights a segment when that resource was close to its limit during that hour, which the cards call pressure. Hover over a segment to see the hour it covers and whether pressure was detected. When the current hour is under pressure, the card also shows how much of that resource your database is using. A single hour of pressure can be temporary.\nL131: Wait and check whether it continues before you resize. The Disk card shows how much data your database reads and writes, not how full your storage is. To check storage, see \ue200cite\ue20245†Increase database storage\ue201 . When any card shows pressure in the last 24 hours, an Instance upgrade recommended notice appears below the cards with an Ask Lovable button.\nL132: Click it to send a chat message that asks Lovable to inspect your database and suggest query or code changes that reduce the load, so you may not need a larger instance. This message is treated as standard build usage and consumes \ue200cite\ue20239†credits\ue201 . Lovable also alerts you when your instance reaches a resource limit. A Cloud instance needs attention notice appears in More → Cloud → Overview and in the project chat, and both open Advanced settings so you can review the cards and resize.\nL133: The project owner also receives a Database limit reached in-app notification that opens the project.\nL134: Before you upgrade, check whether slow queries are the real cause. See \ue200cite\ue20246†Find and fix database performance problems\ue201 .\nL135: ##\nL136: \nL137: \ue200cite\ue20247†\u200b\ue201 L138: \nL139: Upgrade instance\nL140: \nL141: The Database size row shows your current instance size, the computing capacity your database runs on. Click Manage, choose a new size in the Manage instance dialog, and confirm the resize. A larger instance allows your app to handle more users and traffic. A larger instance also increases Cloud usage and uses more credits as your app usage grows.\nL142:   * Free plan users: upgrade from Tiny to a larger instance by upgrading your plan at any time\nL143:   * Paid plan users: choose a new instance size (Tiny, Mini, Small, Medium, Large, or X-Large). Larger sizes handle more traffic and cost more credits per hour while your app runs:\nL144:     * Tiny: great for trying things out\nL145:     * Mini: reliable for early projects\nL146:     * Small: room to grow with your app\nL147:     * Medium: extra capacity for growing apps\nL148:     * Large: steady choice for regular use\nL149:     * X-Large: built for high-demand apps\nL150: A resize takes a few minutes, with a brief interruption while the instance restarts. You can’t make further changes until the resize finishes. You can choose a smaller size again later.\nL151: Database size names changed on July 31, 2026. The size previously called Medium is now called Large, the previous Large is now X-Large, and the previous X-Large is now 2X-Large. Medium is now a new, smaller size that sits between Small and Large.No database was resized or upgraded, and hourly prices did not change. If your project runs on one of the renamed sizes, Advanced settings shows a Database size names updated notice.Some projects run on 2X-Large, the largest size.\nL152: It appears as your current size if your project uses it, but you can’t select it, so a project that moves off it can’t move back.\nL153: ###\nL154: \nL155: \ue200cite\ue20248†\u200b\ue201 L156: \nL157: Ask Lovable to resize your instance\nL158: \nL159: On Pro plans and higher, you can also ask Lovable in the project chat to resize the instance instead of opening Advanced settings yourself. When you describe database slowness, Lovable can offer a resize approval card with a size picker (Tiny through X-Large). The resize only applies after you pick a size and approve it. For example:\nL160: \nL161:     `My database feels slow under load. Resize my Cloud instance to a larger size.\nL162:     `\nL163: Lovable first checks that the instance size, rather than storage or a slow query, is the cause, then offers the size picker. You can also choose a smaller size this way.\nL164: ##\nL165: \nL166: \ue200cite\ue20245†\u200b\ue201 L167: \nL168: Increase database storage\nL169: \nL170: The Database storage row shows how much of your database storage your project uses. If storage is nearly full, click Manage, enter a new size in the Increase database storage dialog, and click Increase storage size. Confirm with Increase storage. When the new size is at least 1.5 times the current size, you also check a box to acknowledge that the increase raises storage costs. A few constraints apply:\nL171:   * The minimum size is 8 GB.\nL172:   * Storage can only be increased, never decreased.\nL173:   * You can change the storage size up to four times within 24 hours.\nL174:   * A resize takes a few minutes. A larger storage size increases Cloud usage.\nL175: ##\nL176: \nL177: \ue200cite\ue20249†\u200b\ue201 L178: \nL179: Database location\nL180: \nL181: The Database location row shows the region your database is hosted in and its PostgreSQL version.
