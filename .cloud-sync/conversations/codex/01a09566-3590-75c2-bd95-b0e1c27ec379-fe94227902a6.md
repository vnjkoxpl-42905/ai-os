# Student roster

**Generated file — do not hand-edit.** Rebuild with:

```
python3 system/scripts/build-roster.py
```

Machine-readable twin: `students/roster.generated.json`, written by the
same run from the same rows. The command center's student picker reads
it through `/api/students`. A folder with no `<slug>.md` page is not a
student and appears in neither file.

Name, email, and status come from the student's own `<slug>.md`
frontmatter (primary, authored). Sessions and last-session come from the
Gemini transcript inventory. To correct a name or email, edit the student's
page and regenerate; editing this file does nothing.

**7Sage** is the second column on purpose: it is a core part of the student's
profile and must never be missed. A linked value means they are set up for the
`7sage-onboarding` / `7sage-update` skills; **⚠️ NOT SET** means their
`7sage_review:` frontmatter URL is missing and they cannot be pulled. The
"Not set up on 7Sage" section below lists every such student.

**Booking columns are read live** from the backend's `booking_passes` on each
rebuild, so they are as fresh as the last run and never a stale local copy.
Revoked passes are not shown: a revoked slug is a dead link.

Written 2026-09-07 after walking it live on lsatprep.study.

Joshua says **"assign &lt;activity&gt; to &lt;student&gt;"** and this is what happens,

## Standing authorization

Joshua granted this on 2026-09-07: assigning an Activity to a **named student**
is a **go** — do it, then report. Do not stop to ask permission first.

## The path

The Activity Centre lives at `/activities` — Classroom sidebar → **Study** →
**Activities**. Joshua's account is admin, so each card in **The library** carries
its own assign button.

1. Navigate to `https://lsatprep.study/activities`
2. `find` the button **"Assign &lt;Activity name&gt;"** (one per card, exact title)
3. Click it — a dialog opens, titled **"Assign: &lt;Activity name&gt;"**
4. Optional: fill **"Schedule for"** (a date input) if Joshua named a due date
5. `read_page` the dialog and locate the student's checkbox by display name
6. Click the checkbox — the footer button updates to **"Assign to 1 students"**
7. Click that button
8. Confirm the result, then report what was sent

The dialog is a portal — it renders **outside `<main>`**, so `get_page_text` will
not show it. Use `read_page` (with the dialog's `ref_id` to keep output small).

## What assigning actually does

`assignWork()` — `projects/lsatu/src/lib/assignWork.ts`:

1. **Snapshots** the Activity into `activity_assignments`. The snapshot is
   immutable once issued, so later content edits do not reach an assignment
   already sent.
2. **Writes a `classroom_items` row** — this is what makes it reachable at all.
3. **Notifies on four channels**: inbox message, bell, email, classroom item.

Notification failure never fails the assignment. A student can therefore hold an
assignment she was never told about — worth checking if she says she got nothing.

// Local calendar-date helpers.
//
// Day boundaries for streaks and daily stats must follow the student's local
// timezone, not UTC. `new Date().toISOString().slice(0,10)` returns the UTC
// calendar date, so any evening practice in a US timezone lands under
// "tomorrow" and breaks streak/day-boundary math. Use these instead.

// Format a Date as its LOCAL YYYY-MM-DD (en-CA yields ISO-style order).
export function localDayISO(date: Date = new Date()): string {
  const y = date.getFullYear();
  const m = String(date.getMonth() + 1).padStart(2, '0');
  const d = String(date.getDate()).padStart(2, '0');
  return `${y}-${m}-${d}`;
}

// Parse a YYYY-MM-DD calendar date into that day's LOCAL midnight.
//
// `new Date('2026-08-05')` is parsed as UTC midnight, which in any western
// timezone is the evening of the 4th. Scheduling work for "the 5th" that way
// unlocks it a day early. Splitting the parts and using the Date(y, m, d)
// constructor keeps the day the day the teacher picked.
export function parseLocalDay(iso: string): Date | null {
  const match = /^(\d{4})-(\d{2})-(\d{2})$/.exec(iso.trim());
  if (!match) return null;
  const [, y, m, d] = match;
  const date = new Date(Number(y), Number(m) - 1, Number(d));
  return Number.isNaN(date.getTime()) ? null : date;
}

// Local date N days offset from `from`, formatted YYYY-MM-DD. Uses setDate so
// it stays correct across DST transitions (unlike subtracting 86_400_000 ms).
export function addLocalDays(days: number, from: Date = new Date()): string {
  const d = new Date(from);
  d.setDate(d.getDate() + days);
  return localDayISO(d);
}
