## 3. "Has this student booked at least one session?"

The canonical read path is the edge function `supabase/functions/student-booking/index.ts` action `info` (`:110-160`), which unions:
- RPC `get_student_booking(auth_uid)` → `redemptions` (`supabase/migrations/20260720190000_booking_phase5_student_state.sql:41-53`, joining `booking_pass_redemptions` → `booking_passes` on `student_id`), and
- `single_session_bookings` filtered `.eq('user_id', userId)`,
tagging each `source: 'redemption' | 'single_session'`.

Concrete condition — a student has booked iff either holds:
```
EXISTS (SELECT 1 FROM booking_pass_redemptions r
        JOIN booking_passes p ON p.id = r.booking_pass_id
        WHERE p.student_id = $uid AND r.status = 'booked')
OR EXISTS (SELECT 1 FROM single_session_bookings
        WHERE user_id = $uid AND status = 'booked')
```
Add `external_booking_events WHERE student_id = $uid AND status='booked'` only if you want Cal.com bookings, which the client already reads separately as `external_bookings`. The client-side equivalent filter is `src/hooks/useBookingScheduleItems.ts:15` (`booking.status === 'booked'`).

Caveat: `single_session_bookings.user_id` is only set when the buyer was signed in; guest purchases match by email only, and Cal.com matching is a best-effort email/name lookup that can leave `student_id` NULL.

## 4. "Session has happened / credits used up"

There is **no attendance signal from any automated path**. Three distinct notions:

- **Time passing** — the only automatic "used" signal. `src/hooks/useBookingScheduleItems.ts:17` computes `completed = new Date(end_at ?? start_at) < now` purely client-side for display; nothing is persisted.
- **Credits consumed** — `booking_passes.used_credits` increments at *redemption* (booking time), not at attendance: `redeem_booking_pass` does `used_credits = used_credits + 1, status = CASE WHEN used_credits+1 >= total_credits THEN 'exhausted' ELSE 'active' END` (latest version `supabase/migrations/20260718234415_...:61-62`). Cancellation refunds the credit (`20260720160000_booking_phase2_atomic_admin.sql:105`). `get_student_booking` also lazily flips `active → exhausted`/`expired` on read (`20260720190000...:13-21`). So "credits used up" = `booking_passes.status = 'exhausted'` OR `used_credits >= total_credits` — it means *fully booked*, not *fully attended*.
- **Attended** — only manual: `booking_pass_redemptions.status = 'no_show'` set by admin action `mark_no_show` (`supabase/functions/booking-pass-admin/index.ts:445-450`), and `student_sessions.status = 'completed'` written by hand or by session-note ingestion (`supabase/functions/_shared/sessionIngestCore.ts:166-213`). `single_session_bookings` has no completed/attended state at all.
