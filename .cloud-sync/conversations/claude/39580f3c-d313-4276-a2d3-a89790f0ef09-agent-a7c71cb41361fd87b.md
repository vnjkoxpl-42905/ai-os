## 5. What I would escalate

**High, process. The assessment's own scan command was broken and failed silently.** This is a bigger problem than anything in the Testing Centre. `npx impeccable <files>` with no subcommand exits 0 with empty output, which reads exactly like a pass. Whatever runbook or skill produced that command line should be corrected to `impeccable detect`, and the harness should treat "exit 0 with completely empty stdout and stderr" as suspect rather than clean. A positive control (scan a directory known to have findings) is cheap and would have caught this.

**Medium, process. The instruction to exclude the CSS was based on a false premise, and it excluded the only file with findings.** The scanner handles CSS. Excluding stylesheets from a *visual* audit removes the layer where visual defects actually live.

**Low, real product drift. The 15px type step is undocumented but pervasive.** `testing-centre.css:21` is one instance of at least fourteen across the app (`QuestionPicker.tsx` alone has eight at lines 854, 941, 1005, 1050, 1141, 1198, 1283, 1322, plus `AssistantComposer.tsx:514`, `DeskChatRail.tsx:104`, `DraftReplyCard.tsx:286`, `TutorChatModal.tsx:548`, `canvasExports.ts:115`). At that frequency 15px is a de facto step in the system that DESIGN.md refuses to acknowledge. Either add it to the `typography:` block or snap these to 14px. Leaving it is what generates recurring advisory noise that trains people to ignore the detector. Note that `.impeccable/config.json` already contains a sanctioned ignore for exactly this class of problem covering 14/18/20px, with the reasoning that "the detector reads only the `typography:` YAML block at line 38, which omits them"; 15px looks like the same situation and was simply never added.

**Low. No display type step exists.** `56px` at `testing-centre.css:336` has nowhere legitimate to live in the documented ramp. Adding a `display:` entry to DESIGN.md would resolve this finding honestly rather than by suppression.

**Info.
