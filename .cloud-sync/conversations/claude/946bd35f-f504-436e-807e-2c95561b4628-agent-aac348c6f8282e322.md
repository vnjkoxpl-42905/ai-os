## 0. Four hard facts from `who_am_i` that change the plan

1. **`prefer_multi_shots` defaults to `true` on `kling-video-v3_0` image_to_video.** The model will cut to an invented second shot mid-clip. 2. **Seed stills must be BELOW 4K.** The live `image_to_video` tool declaration reads: "Supported image specs: PNG/JPG only, below 4K resolution, ≤30MB, aspect ratio no wider than 1:2." So seeds are authored at `2k`. A 4k seed is rejected as an input. Video output is still 4k.
3. **`kling-image-v3_0` caps at `2k` and defaults to `3:4`.** It cannot make a 4k still and it will not give 16:9 unless told. The 4k-capable image models are `kling-image-v3_0_omni` (default 4k) and `gemini-3-pro-image`. Since point 2 forbids 4k seeds anyway, resolution is not the deciding factor; prompt adherence is.

## 1. The architectural decision that makes the composite safe

**The monitor is only ever composited pixel-correct while the plate is locked off.** Every camera move in the plate set either leaves the monitor entirely, or leaves it defocused at the edge of frame.

Reason in one line: a generative dolly has parallax that no analytic transform reproduces, so text under it would swim, while a locked plate needs no tracking at all.

Consequence per plate, and this is the data Remotion needs for the floating popup layer:

| Plate | Camera move | Analytic model for Remotion | Screen composite |
|---|---|---|---|
| A | none | identity | pixel-correct, static rect |
| B | pan left | x-translation, power2.inOut | blurred, 2-key corner match |
| C | none | identity | monitor not in frame |
| D | pan right | x-translation, power2.inOut | blurred until settle, then identity |
| E | tilt up | y-translation, power2.inOut | monitor not in frame after 0.8s |
| F | axial push | uniform scale about frame centre | near-blank screens only |

All five moves are invertible in one line of code, so the popups can be parented to room space and hang still while the camera moves past them.

**The Space press needs no plate.** With no hands in frame it is carried by a four-frame Remotion blink (soft eyelid wipe), a key thunk, and the screen state change. That is the strongest POV idiom available and it costs zero credits. Plate F's push covers the commitment beat around it.

## 4. How the room stays identical across plates

Five mechanisms, layered, so no single failure breaks continuity:

1. **One master still.** S1 is generated once. Nothing else is ever prompted from a blank page.
2. **Derived, not re-prompted.** S2 and S3 come from `image_to_image` with S1 as the reference, so the wall colour, light direction, desk wood and window all carry over rather than being re-invented.
3. **Never `text_to_video`.** Every clip is `image_to_video` off one of those three stills, so each plate's first frame is a known, locked pixel.
4. **`--tailImage` on every transition plate.** B ends on S2, D ends on S1, E ends on S3. B and D are exact inverses with pinned endpoints, so the room at every cut point is provably the same image, not a lookalike.
5. **`--prefer_multi_shots false` everywhere.** Without it the model is free to cut to a fabricated second shot inside a single clip, which no amount of seeding can undo.

The monitor's own stability is prompt-enforced: square on, screen plane parallel to the image plane, no keystone, matte anti-glare, window turned away from the panel's line of sight so no reflection can crawl across it, and a thin straight bezel so all four screen corners are unambiguous for the corner pin.

## The RRC walkthrough

`RRCWalkthrough` shows a real run of PT105 Section 2, questions 1 to 3, with
Joshua's own model-run recordings as the audio and a teaching overlay on top.

```bash
npm run dev                                  # studio
```

## Two machine-specific gotchas

- **rspack emits no JavaScript here.** `Config.setRspack(true)` (which
  `create-video` writes when you accept Tailwind) prints "Bundling 100%", exits
  0, and produces only `index.html`. The resulting `ENOENT ... bundle.js` is a
  decoy: it is the source-map reader failing, not the real fault. It is
  commented out in `remotion.config.ts`. Do not re-enable without testing a render.
- **npm blocks install scripts**, so esbuild's binary never installs. Fix with
  `npm approve-scripts esbuild`.

## How the overlay stays in sync

1. `align/transcribe.py` runs faster-whisper over the three MP3s for word-level
   timestamps. Agreement with the stored Deepgram transcripts is 96.8 to 98.0%.
2. `align/timeline.js` aligns `walkthrough_md` to that word stream with global
   Needleman-Wunsch, giving the exact span where each Chunk is read aloud.
   Fuzzy anchoring was tried first and drifted; do not go back to it.
3. `align/copycheck.js` checks on-screen copy against the banned vocabulary in
   `activity-centre/CONTEXT.md`.

Colours and type in `src/rrc/tokens.ts` are sampled from the real
`recall/section.css`. Re-sample rather than eyeball if it changes.

**Layout law:** the teaching layer owns a 96px band across the top and never
overlaps the replicated app. The first cut floated it over the app's header rail
and clipped it, which is exactly the confusion the design forbids.

## Known gap: The Recall

whole argument back from memory. Verified against the Whisper transcripts, the
