See a feature in an app that you want in your own product? Ask your agent to investigate it with REA. It can inspect the app without its source code, explain how the feature works, show the evidence, and build a version for your project.
REA connects your agent to tools for inspecting native binaries, JavaScript and Electron apps, .NET assemblies, and websites. You can also use the same tools from your terminal. Analysis runs locally, and results include the evidence and limitations behind each conclusion.
Setup registers REA with your agent and installs matching workflow instructions. Native analysis can use an existing Hopper, Ghidra, or IDA installation; setup can optionally install Hopper with approval. Static JavaScript analysis needs no native analysis engine.
> **[Visit the REA website](https://rea.tools/)** for setup instructions, illustrated guides, and real case studies.
## Quick start
### Set up your agent
With Node.js and npm installed, run:
```bash
npx rea-agents setup
```
Choose your agents, review the proposed changes, and approve them. Setup adds
REA's MCP server and matching workflow instructions, with backups of existing
configuration. Restart your agent afterward.
Setup supports Claude Code, Codex, Cursor, Gemini CLI, Grok Build and
[other agents](docs/installation.md#supported-agents). See
[installation and setup](docs/installation.md) for provider configuration and
manual MCP registration.
### Ask your agent
```text
Understand how search works in the Notes app, show me the evidence, and build a
similar feature for my project.
```
Replace Notes with your target app and the feature you want to understand.
### Use the terminal
Inspect an extracted JavaScript/Electron app directory or ASAR:
```bash
npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json
```

## assistant

**What Rea does:** You show it software that already exists (an app, a website, an Electron or JavaScript program). It opens that software up with analysis tools and reports how a feature works, with evidence. Then your agent can build a similar feature for your own project.

**How it works under the hood:**
1. You ask Claude a plain-English question about an app.
2. Claude calls the Rea MCP.
3. Rea drives the analysis tools: Ghidra for native apps, Chrome DevTools and static code reading for websites and Electron/JavaScript apps.
4. It returns pseudo-code, the proof behind each conclusion, and a list of unknowns.
5. Claude uses that to write your version, and loops until it matches.

**How to use it:** Restart Claude Code first, then type requests like these:

```text
Use Rea to understand how search works in [app or site], show me the evidence, and build a similar feature for my project.
```

```text
Use Rea to analyze the website https://example.com and explain how its checkout flow works.
```

```text
Use Rea to take apart the Electron app at C:\path\to\app and list its main features.
```

The skill is called `reverse-engineer-anything`. It loads when your request is about taking apart shipped software.

**From a terminal (no Claude):**

```bash
rea analyze-javascript-application C:\path\to\app --json
```

```bash
rea doctor
```

**Limits to know:**
- It works best on websites, JavaScript/Electron apps, and apps you can point it to on this Windows machine. Native Mac apps, like the Preview demo in the video, need a Mac.
- Ghidra is set up, but I only tested the JavaScript analysis, not a native one.
- Use it only on software you own or have the right to inspect. Copying a commercial app is an IP problem.
