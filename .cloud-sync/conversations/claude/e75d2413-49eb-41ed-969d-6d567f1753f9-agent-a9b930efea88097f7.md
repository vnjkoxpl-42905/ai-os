## Confirmed defects, most serious first

**1. Indicator selection is never checked in Drills 7, 8 and both Revisit drills** (`SourceWorksheetDrill.tsx:88`, `:125`). This answers your question (1): it is a defect, not intended. `deferredComparison` is true for every step when `taskKind === 'contrapositive'`, and the Revisit drills are built with that same kind (`sourceWorksheetDrills.ts:3704-3718`). So "Find the indicators" shows the "model stays hidden" line and "Save and continue". A student can mark "only if" as Group 1 and nothing stops them. The model indicators only appear on the final review, with nothing flagging the mismatch.
- **Fix:** defer only the writing steps. Set `deferredComparison` only when `production && stage !== 'indicators'`, so the indicator step uses the normal blocking check.

**2. Signed-in students' work goes to a shared "preview" key, not a per-student one** (`OpeningCourse.tsx:58`, `:123`). `<SourceWorksheetDrill>` is never given `storageScope`, so the live route (`routes.tsx:189`) always uses `conditional-worksheet-v1:<set>`. The comment at `SourceWorksheetDrill.tsx:51` says signed-in users never use that key, which is false. Two students on one device would overwrite each other's Drills 2-8, and nothing is saved to their accounts.
- **Fix:** pass the user id as `storageScope`.

**3. Drill 1 lets a wrong answer move on and reintroduces the save notice** (`DrillOneExperience.tsx:113`, `:109`, `:94`).
- "Next question" only needs the answer to have been checked. A wrong answer also marks the correct option on screen.
- Line 94 says "These results stay in this practice session. They are not saved to your account." That is the removed notice in another form.
- Answers live only in component state, so a reload loses all 24.
- **Fix:** require a correct answer before Next, don't reveal the answer on a wrong attempt, persist answers, and delete line 94.

**4. Must-arrow practice has the progress style Joshua rejected, and wrong answers don't block** (`MustArrowPractice.tsx:96`, `:102`, `:128`). It shows "{count} answered · {n} remaining". A wrong answer locks the choices, reveals the answer (line 120), and still enables Next.
- **Fix:** allow a retry and gate Next on a correct answer.

**5. The answer check rejects the answer key's own indicator** (`sourceWorksheetDrills.ts:226`, Intro #8). The model indicator is "Members who", but the intro answer key says "who". Because the check needs an exact match (`SourceWorksheetDrill.tsx:84`), a student who selects "who" is blocked in Drill 2. "Members" is not an indicator.
- **Fix:** change the model indicator to "who".

**6. The mixed-practice save notice (your question 3) is accurate but shouldn't be needed** (`OpeningCourse.tsx:16`, `:69`, `:121`). `OpeningMixedDrill` really has no persistence, so the notice is true. But it appears twice, and it admits a 24-question drill loses everything on reload.
- **Fix:** persist the drill like the others, then remove the notice.

**7. Contrapositive wording uses "that" before anything has been introduced.** Many items do this, for example Drill 7 #1: "If that intern is not offered a full-time position, then that person is not an intern who completes the program". The same pattern appears in Intro #4, #5, #8, #13 and #14, and in Drill 7 #7. "That intern … is not an intern" reads as a contradiction, and the contrapositive should read cleanly.
- **Fix:** start the contrapositive with "a person" or "someone", for example "If a person is not offered…".

**8. Drill titles name questions, not tasks** (`openingCoursePath.ts:17`, `DrillOneExperience.tsx:27`). The title is "Drill 1", and the entry heading is "Drill *1*".
