Five of the seven items already have real data. The practice test (PT) score history is the main gap, and the starting and goal scores exist only as score ranges, not exact numbers.

**1. Latest PT score and trend: PARTIAL**
- The `practice_test_runs` table has `pt`, `scaled_score`, `score_source`, `completed_at` and `status` (types.ts:3126, migration `20260829120000_practice_test_runs.sql:93`). No code in `src/` reads or writes it.
- The app saves in-app runs to localStorage only (`src/lib/practiceTest.ts:340`, `listPracticeTestRuns` at :361). Score is estimated from raw correct by `estimateScaledScore` (:279).
- Scores imported from other platforms are in `student_external_metrics` where `metric_kind='pt_score'`. Read them with `useStudentExternalMetrics().ptScores` (`src/hooks/useStudentExternalMetrics.ts:52`).
- Effort: medium. Easiest now is imported scores plus localStorage runs. A real trend line needs PT runs written to the table.

**2. Questions answered this week: EXISTS**
- `daily_stats.questions_answered` per `class_id` and `date` (types.ts:1585). `useStudentAnalytics` only reads today's row (`src/hooks/useStudentAnalytics.ts:53`).
- Effort: low. One query for the last 7 days, summed.

**3. Sessions left on the booking pass: EXISTS**
- Table `booking_passes` has `total_credits` and `used_credits` (types.ts:1131).
- Home already calls `useStudentBooking()` (`useClassroomHome.ts:176`), which returns `pass.credits_remaining` (`src/hooks/useStudentBooking.ts:9`).
- Effort: trivial. Pass it through `homeModel`.

**4. Days until test date: EXISTS**
- `profiles.test_date` is set per student, null when undecided (types.ts:3225). It's written during onboarding (`OrientationCard.tsx:342`) and in `PrepSection.tsx:213`.
- Home already has a `daysUntil()` helper (`useClassroomHome.ts:123`).
- Effort: low. One `profiles` select.

**5. Goal score and starting score: PARTIAL**
- Onboarding stores ranges, not numbers: `target_score_band` and `last_score_band` in the `profiles.onboarding` JSON (`src/lib/onboarding.ts:94-100`). The ranges are listed at :13, e.g. `156_160`. Either can also be "not sure" or "not taken".
- Effort: low to medium. Use the middle of each range, or add number columns for exact scores. The starting score could instead fall back to the first PT score.

**6. Accuracy by question type: EXISTS**
- The RPC `attempt_accuracy_rollup(p_class_id)` returns `qtype`, `correct` and `total` (types.ts:5821). The Analytics page uses it (`src/pages/Analytics.tsx:55`) together with `computeAnalyticsFromRollup` (`src/lib/analyticsRollup.ts:39`).
- There's also a cached copy in `profiles.by_qtype_json`, and raw rows in `attempts.qtype` and `correct` (types.ts:594).
- Effort: low. Reuse the RPC, sort by accuracy, and set a minimum number of questions per type.

**7. Days studied this month, and session dates: EXISTS / PARTIAL**

- Tutoring session dates: `useStudentBooking().bookings[].start_at`. The edge function returns the last 30, past and future (`supabase/functions/student-booking/index.ts:108-115`).

- Effort: low for the calendar. Session dates are already on Home through the booking hook.
