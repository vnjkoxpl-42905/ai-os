# One-off booking links

A URL Joshua sends to one person. She opens it, books one session, pays, and
gets the Google Meet invite from the ordinary booking flow. Then the link
closes.

## Authorization

Minting a link is pre-authorized. Joshua asking for a link means make it now —
do not ask permission, ask only for the facts you actually need.

**Never send the link anywhere.** Print it and hand it to Joshua. He decides who
gets it. A link is a Bearer [REDACTED]: whoever holds it can book that slot.

## What you need before running

Only two things are required, and one has a default:

- **Price** in dollars. Required — links always charge, and the standard rate is
  $45 but a given person may pay something else. Ask if it was not said.
- **Who it is for.** Used only for the admin-side note, never in the URL. If
  Joshua did not say, use a short description.

Everything else is optional. Ask for nothing you were not given.

## Running it

From `~/ai-os/projects/lsatu`:

```bash
npm run booking:link -- --for "Dakota" --price 45 --at "2026-09-10 19:15"
```

Times in `--at` are wall-clock in Joshua's booking timezone (`America/Toronto`),
format `YYYY-MM-DD HH:mm`, 24-hour. Convert "7:15pm tomorrow" yourself — resolve
relative dates against today before running, and never pass a relative word
through.

It prints the URL, the price, the time, and how many times the link can sell.
Give Joshua the URL exactly as printed.

### The flags

| Flag | Default | What it does |
|---|---|---|
| `--for` | — | Who the link is for. Note only, never in the URL. |
| `--price` | — | Dollars. Required. |
| `--at` | none | Pin one exact time. See below. |
| `--minutes` | 70 | Session length. |
| `--notice` | 1440, or 0 with `--at` | Minimum notice in minutes. `0` means "bookable right now". |
| `--window` | 6 | How many business days ahead the picker reaches. |
| `--label` | "LSAT Session" | The title she sees on the page. |
| `--note` | auto | Admin reminder of who and why. |

### Pinned versus picker

**`--at` pins one time.** She sees only that time and confirms it. The minimum
notice, the rolling window and the weekly hours are all skipped, because Joshua
choosing the time *is* that decision. This is the right shape for "I have a gap
at 7:15 tonight, let her take it."

**Without `--at` she gets a calendar** of open times, still inside the weekly
hours. Use `--notice 0` for a short-notice link she can book today, and
`--window` to control how far ahead it reaches.

Double-booking is never skipped either way. A pinned time that clashes with
something already on the calendar is refused at mint time — the script deletes
the link and tells you what it hit — and refused again inside the booking
transaction.

## Listing and revoking

```bash
npm run booking:link -- --list
npm run booking:link -- --revoke <slug>
```

`--list` shows every one-off link with its state: `open`, `used`, or `revoked`.
Revoking is immediate and the URL stops resolving.

## Reading the outcome honestly

- **"clashes with something already on your calendar"** — the time is taken. No
  link was created. Tell Joshua what he asked for is not free and offer to pick
  another time; do not silently mint a different one.
- **"would have no open times at all"** — a picker link whose window and weekly
  hours produce nothing. Usually `--window` is too small or the hours are empty.
- **A time in the past** is refused. If Joshua asks for a time that has already
  gone by today, say so rather than rolling it to tomorrow on your own.

## How it works, so you can debug it

A one-off link is a row in `booking_event_types` with a random 10-character slug
and `single_use` set. That is the same table defining the ordinary session and
the consultation, and every layer beneath — the page, the `single-session` edge
function, the SQL slot policy, the claim transaction — is already keyed by event
slug. So the link books through exactly the code a normal session books through.
There is no second booking path to keep in sync.

Single use is enforced by the `enforce_booking_event_shape` trigger under a
per-slug advisory lock, so two people opening the same link at the same moment
cannot both get through. A hold holds the link; letting the checkout expire
releases it; a cancelled or refunded booking stays spent, and a replacement
needs a fresh link.

-- Student self-serve booking, phase 1 (core loop: grant -> book -> see in calendar).
-- Reschedule / compensation / reconciler are a later phase and NOT in this migration.
--
-- What this adds:
--   1. reschedule_count column on redemptions (guard column for the later phase; harmless now)
--   2. one-active-pass-per-student invariant (dedup existing rows, then a partial unique index)
--   3. grant_booking_access(...)  RPC  -- atomic revoke-active + insert, per-student advisory lock
--   4. get_student_booking(...)   RPC  -- safe DTO for the authenticated student (NO token_hash)
-- All RPCs are SECURITY DEFINER, service_role-only, SET search_path = public,
-- matching the existing redeem_booking_pass pattern.

-- ---------------------------------------------------------------------------
-- 1. reschedule_count column (idempotent; ensure the CHECK exists even if the
--    column somehow pre-exists without it)
-- ---------------------------------------------------------------------------
ALTER TABLE public.booking_pass_redemptions
  ADD COLUMN IF NOT EXISTS reschedule_count int NOT NULL DEFAULT 0;

DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_constraint
    WHERE conrelid = 'public.booking_pass_redemptions'::regclass
      AND conname  = 'booking_pass_redemptions_reschedule_count_ck'
  ) THEN
    ALTER TABLE public.booking_pass_redemptions
      ADD CONSTRAINT booking_pass_redemptions_reschedule_count_ck
      CHECK (reschedule_count >= 0 AND reschedule_count <= 1);
  END IF;
END$$;

-- ---------------------------------------------------------------------------
-- 2. One active pass per student. Resolve existing data first so the unique
--    index can be created, then create it. Re-runnable (second run is a no-op).
-- ---------------------------------------------------------------------------

-- a) Expire stale 'active' rows whose expiry has passed (the app only expires on read).
UPDATE public.booking_passes
   SET status = 'expired'
 WHERE status = 'active'
   AND expires_at IS NOT NULL
   AND expires_at < now();

-- b) Among remaining active rows for the same student_id, keep the newest, revoke the rest.
WITH ranked AS (
  SELECT id,
         row_number() OVER (PARTITION BY student_id ORDER BY created_at DESC, id DESC) AS rn
    FROM public.booking_passes
   WHERE status = 'active' AND student_id IS NOT NULL
)
UPDATE public.booking_passes b
   SET status = 'revoked'
  FROM ranked r
 WHERE b.id = r.id
   AND r.rn > 1;

-- c) The invariant. NULL student_id rows (name/email-only passes from the
--    standalone page) are exempt: multiple NULLs are allowed under a partial index.
CREATE UNIQUE INDEX IF NOT EXISTS one_active_pass_per_student
  ON public.booking_passes (student_id)
  WHERE status = 'active' AND student_id IS NOT NULL;

-- ---------------------------------------------------------------------------
-- 3. grant_booking_access: atomically revoke any active pass for the student
--    and insert a fresh one. The caller (edge fn) generates the raw token and
--    passes only its sha256 hash (RPC never sees the raw token; token_hash NOT NULL
--    is satisfied). A per-student transaction advisory lock serializes two
--    concurrent first-grants even when no row exists yet (FOR UPDATE cannot lock
--    a nonexistent row).
-- ---------------------------------------------------------------------------
CREATE OR REPLACE FUNCTION public.grant_booking_access(
  _student_id   uuid,
  _student_name text,
  _student_email text,
  _total_credits int,
  _session_length_minutes int,
  _expires_at   timestamptz,
  _created_by   uuid,
  _token_hash   text
) RETURNS public.booking_passes
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  _new public.booking_passes;
BEGIN
  IF _student_id IS NULL THEN
    RAISE EXCEPTION 'student_id_required' USING ERRCODE = 'P0400';
  END IF;

  -- Serialize per student, including the no-existing-row case.
  PERFORM pg_advisory_xact_lock(hashtextextended(_student_id::text, 0));

  UPDATE public.booking_passes
     SET status = 'revoked'
   WHERE student_id = _student_id
     AND status = 'active';

  INSERT INTO public.booking_passes
    (token_hash, student_id, student_name, student_email,
     total_credits, session_length_minutes, expires_at, created_by)
  VALUES
    (_token_hash, _student_id, _student_name, _student_email,
     GREATEST(1, LEAST(50, _total_credits)),
     GREATEST(15, LEAST(480, COALESCE(_session_length_minutes, 60))),
     _expires_at, _created_by)
  RETURNING * INTO _new;

  RETURN _new;
END;
$$;

REVOKE ALL ON FUNCTION public.grant_booking_access(uuid, text, text, int, int, timestamptz, uuid, text) FROM public, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.grant_booking_access(uuid, text, text, int, int, timestamptz, uuid, text) TO service_role;

 * One-off booking links: mint a URL that sells exactly one session, at a price
 * you set, and then stops working.
 *
 * A one-off link is not a new booking system. It is a row in
 * `booking_event_types` -- the same table that defines the ordinary session and
 * the consultation -- with a random slug and `single_use` set. Every layer
 * beneath it (the page, the edge function, the slot policy, the claim
 * transaction) is already keyed by event slug, so the link books through
 * exactly the code a normal session books through.
 *
 * Two knobs make it useful for short notice:
 *
 *   --at      pins one exact time. The link offers only that time, and the
 *             notice, window and weekly-hours rules do not apply -- you already
 *             decided this hour is fine by choosing it. A genuine clash with
 *             your calendar still blocks it, both here and at booking time.
 *   --notice  how far ahead someone must book, in minutes. 0 means "any time
 *             from now". Only meaningful without --at.
 *
 *   npx vite-node scripts/booking-link.ts -- --for "Dakota" --price 45 --at "2026-09-10 18:00"
