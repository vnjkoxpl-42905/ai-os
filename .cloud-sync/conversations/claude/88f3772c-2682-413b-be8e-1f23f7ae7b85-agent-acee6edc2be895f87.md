128	 * mis-kinded silently. This is the only thing that surfaces it. Four of the
129	 * 1,294 authored Details trip it and all four are correctly content; a section
130	 * whose residue is growing has drifted from the authoring vocabulary.
131	 */
132	export function isKindResidue(text: string, kind: DetailKind): boolean {
133	  const t = text.trim().toLowerCase();
134	  return kind === "content" && t.startsWith("this is") && !CONTENT_DESPITE_OPENING.test(t);
135	}

138	  return texts.map((text, i) => ({ n: i + 1, text, kind: classifyDetail(text) }));

160	export interface JudgeEntry {
161	  id: number;
162	  text: string;
163	  kind: DetailKind;
164	  /** Not sent to the model. A decoy must come back missed. */
165	  decoy: boolean;
166	  /** The authored line this Detail belongs to, when known. Never on a decoy. */
167	  line?: number;
168	}
169	
170	/**
171	 * The list the judge is shown: the stimulus's own Details plus decoys.
172	 *
173	 * Decoys are Details belonging to a DIFFERENT stimulus in the same section, and
174	 * the only correct verdict on one is "missed". They are the per-run check on the
175	 * failure mode that matters, which is the judge reasoning "the stimulus says
176	 * this, so she must have meant it" and crediting her for words she never said.
177	 * That failure is invisible in the output -- it just looks like a good score --
178	 * so something has to be able to catch it in the run itself rather than in
179	 * aggregate.
180	 *
181	 * Interleaved deterministically rather than shuffled, so the same inputs give
182	 * the same prompt and a disagreement between two runs is the model's, not ours.
183	 */
184	export function buildJudgeEntries(details: Detail[], decoyTexts: string[]): JudgeEntry[] {
185	  const real = details.map((d) => ({ text: d.text, kind: d.kind, decoy: false, line: d.line }));
186	  const decoys = decoyTexts.map((text) => ({ text, kind: classifyDetail(text), decoy: true }));
187	
188	  if (decoys.length === 0) return real.map((e, i) => ({ id: i + 1, ...e }));
189	
190	  // Spread them through the list instead of appending: a judge that sees two
191	  // odd items at the end can treat the tail as a different question.
192	  const step = Math.max(1, Math.floor(real.length / (decoys.length + 1)));
193	  const out: Omit<JudgeEntry, "id">[] = [];
194	  let next = 0;
195	  real.forEach((entry, i) => {
196	    out.push(entry);
197	    if (next < decoys.length && (i + 1) % step === 0) out.push(decoys[next++]);
198	  });
199	  while (next < decoys.length) out.push(decoys[next++]);
200	  return out.map((e, i) => ({ id: i + 1, ...e }));
201	}

203	/**
204	 * Which Details from another stimulus can serve as decoys.
205	 *
206	 * A decoy is a Detail she cannot have carried, so crediting one means the judge
207	 * invented words she never said. That only holds if the decoy is a fact about
208	 * the OTHER stimulus. A structural Detail -- "This is the reason given." -- is
209	 * a fact about arguments rather than about any stimulus, and almost any honest
210	 * retelling carries it. The trial run's single decoy failure was exactly that,
211	 * and it was ours: the integrity check reported the judge hallucinating when
212	 * the judge was right, which is the worst possible direction for a check whose
213	 * whole job is to be trusted.
214	 *
215	 * Modality is excluded for the same reason and is a weaker case: "This is
216	 * hedged." is about a claim, but the hedge it names is common enough across
217	 * stimuli to be carried honestly.
218	 *
219	 * Drawn across the whole stimulus rather than from its first chunk, which is
220	 * where the structural Details tend to live.
221	 */
222	export function pickDecoys(details: string[], howMany = 2): string[] {
223	  return details.filter((text) => classifyDetail(text) === "content").slice(0, howMany);
224	}

226	const KIND_RULE: Record<DetailKind, string> = {
227	  content:
228	    'CONTENT — a fact. Carried if she stated it, in any words, in any order. ' +
229	    'Synonyms and paraphrase count fully. A dropped proper noun, number or ' +
230	    'quantifier is NOT carried: "all employees" is missed if she said "the staff".',
231	  structure:
232	    'STRUCTURE — a discourse role, not words. Carried if the relationship is ' +
233	    'present in HOW she told it; she never has to name it. "This is a contrast." ' +
234	    'is carried by a "but", a "though", or "X is different from Y". "This is the ' +
235	    'conclusion." is carried by a "so" or "therefore" introducing that claim.',
236	  modality:
237	    'MODALITY — the strength of the claim. Carried if her qualifier survived. ' +
238	    'A flat assertion where the source hedged is NOT carried.',
239	};

241	export function buildJudgePrompt(input: {
242	  stimulus: string;
243	  entries: JudgeEntry[];
244	  spoken: string;
245	  /**
246	   * The analytical takeaway she should have arrived at, authored on every one
247	   * of the 1,294 stimuli and, until now, graded by nothing.
248	   *
249	   * Coverage answers "did you hold it". The Read answers "did you understand
250	   * it", and it is the criterion the method is actually built around: the
251	   * briefing tells her "this is the part that gets checked", the coach rubric
252	   * says to score it, and the section spec makes it the drill's accuracy
253	   * criterion. Omit it and the run is judged on memory alone, exactly as it was.
254	   */
255	  theRead?: string | null;
256	  /**
257	   * One correct run of THIS stimulus, as a document: the verbatim read of each
258	   * chunk, then the recall of it in his own words.
259	   *
260	   * The judge had no example of good work. It carried a checklist of facts and
261	   * a one-line key for The Read, and was then asked whether her run was a flat
262	   * list, whether she engaged with the stimulus at all, and whether that
263	   * engagement was specific to it -- three judgments about quality made against
264	   * nothing but the model's own idea of quality. This is the standard those
265	   * three are measured against, and it is the standard a person set.
266	   *
267	   * It is emphatically NOT a target to match. A student who reproduced this
268	   * would be reciting, which is itself a failure the same prompt checks for.
269	   * The prompt says so at some length, because an exemplar dropped into a
270	   * grading context without that framing turns into an answer key, and every
271	   * run that differs from it starts looking wrong.
272	   */
273	  modelRun?: string | null;
274	  /**
275	   * Her run cut into the lines she was rephrasing, and her whole-stimulus
276	   * recall on its own.
277	   *
278	   * The drill is line by line -- read one line silently, look away, say that
279	   * line back -- and until now the judge saw the whole thing as one block of
280	   * text. It could say a fact was dropped; it could not say WHERE, which is the
281	   * only form of that feedback she can act on. The cut comes from the silence
282	   * before each spoken line (`rrcLines.ts`), so it is evidence about her run
283	   * and not a boundary she is scored against.
284	   */
285	  lines?: { n: number; text: string; spoken: string }[];
286	  /** What she said after the text disappeared. Part of `spoken` as well. */
287	  recall?: string | null;
288	}): string {
289	  const kinds = [...new Set(input.entries.map((e) => e.kind))]
290	    .map((k) => `- ${KIND_RULE[k]}`)
291	    .join("\n");
292	  const list = input.entries
293	    .map((e) => `${e.id}. [${e.kind}] ${e.text}`)
294	    .join("\n");
295	
296	  return `You are grading one stimulus of a memory drill.
297	
298	The student read the stimulus one line at a time. She reads a line silently,
299	looks away from the screen, and says that line back out loud in her own words
300	from memory; then the next line, and so on. When every line is done the text
301	disappears and she restates the whole stimulus from memory. She never reads
302	aloud. Your job is to decide, for each numbered Detail, whether she carried it.
303	
304	THE STIMULUS (context only — see the rule below):
305	"""
306	${input.stimulus}
307	"""
308	
309	WHAT SHE SAID (this is your ONLY evidence):
310	"""
311	${input.spoken}
312	"""
313	${
314	    input.lines?.length
315	      ? `
316	HER RUN, LINE BY LINE (the same words, split by which line she had just read):
317	${input.lines
318	          .map((l) => `Line ${l.n}: ${l.text}\n  She said: ${l.spoken || "(nothing)"}`)
319	          .join("\n")}
320	${input.recall ? `\nHER FULL RECALL, text off screen:\n"""\n${input.recall}\n"""\n` : ""}
321	Judge each line: how much of that line survived in what she said for it, and
322	say in one short sentence what she dropped. A line she said nothing for is
323	"skipped". Then judge the full recall the same way. The split is approximate --
324	if she clearly covered a line's content while talking about a neighbouring
325	line, do not mark it skipped.
326	`
327	      : ""
328	  }
329	
330	
331	HOW TO JUDGE EACH KIND:
332	${kinds}
333	
334	RULES:
335	- Judge ONLY from what she said. NEVER mark a Detail carried because the
336	  stimulus contains it. The stimulus is there so you know what a Detail refers
337	  to, not as evidence that she said it. This is the most important rule here.
338	- Some of the Details below belong to a DIFFERENT stimulus and she cannot have
339	  carried them. Mark those not carried. Do not try to guess which.
340	- When you are genuinely torn, mark it NOT carried.
341	- Her transcript may contain mangled or clipped words. Judge the substance.
342	
343	THE DETAILS:
344	${list}
345	
346	${
347	    input.theRead
348	      ? `THE READ she should have arrived at:
349	"""
350	${input.theRead}
351	"""
352	
353	Judge her Read, from what she said and nothing else:
354	- read_given: did she say anything analytical about what the argument is DOING
355	  -- its move, its flaw, what turns on it -- as opposed to retelling what it
356	  says? Retelling alone is not a Read.
357	- read_matches: did what she said amount to the SAME move as THE READ above? A
358	  different name for the same move is fine; missing the move is not. She is not
359	  expected to use its words, and it may be shorter or messier than the key.
360	
361	`
362	      : ""
363	  }${
364	    input.modelRun
365	      ? `A CORRECT RUN of this same stimulus, for calibration:
366	"""
367	${input.modelRun}
368	"""
369	
370	How to use it, and how not to:
371	- It sets the STANDARD, not the answer. It is one good run, not the only one.
372	  Her wording, her examples, her order and her emphasis can all differ from it
373	  completely and still be just as good.
374	- Use it for the whole-run judgments below: this is what "not a flat list" and
375	  "reacted to the stimulus" look like at the level expected here.
376	- Do NOT use it as evidence. A Detail is carried only if SHE said it. If it
377	  appears here and not in what she said, it is not carried. The verdicts above
378	  are decided from her words alone.
379	- Do NOT reward similarity to it or penalise difference from it. Matching its
380	  phrasing closely is a warning sign, not a good score: that is reciting.
381	
382	`
383	      : ""
384	  }Also judge the run as a whole:
385	- reciting: did she say the stimulus back close to word-for-word rather than
386	  retelling it? Full coverage reached by reciting is a failure.
387	- listing: did she deliver it as a flat run of facts rather than as a connected
388	  argument?
389	- coloured: did she react to the stimulus at all — a thought, doubt, example or
390	  joke — beyond retelling it?
391	- colour_specific: was that reaction specific to THIS stimulus rather than
392	  something that would fit any stimulus?
393	- big_misses: at most three short phrases naming the most important things she
394	  dropped, in plain words she can act on. Empty if she dropped nothing that
395	  matters.
396	
397	Reply with JSON only, no prose and no code fence:
398	{"verdicts":[{"id":1,"carried":true}],"reciting":false,"reciting_reason":"",
399	"listing":false,"listing_reason":"","coloured":true,"colour_specific":true,
400	"big_misses":[]${
401	    input.theRead ? ',\n"read_given":true,"read_matches":true,"read_reason":""' : ""
402	  }${
403	    input.lines?.length
404	      ? ',\n"lines":[{"n":1,"verdict":"strong","note":""}],\n"recall":{"verdict":"partial","note":""}'
405	      : ""
406	  }}
407	${
408	    input.lines?.length
409	      ? `\nEvery line verdict is one of: strong, partial, thin, skipped. Return one\nentry for every line from 1 to ${input.lines.length}.\n`
410	      : ""
411	  }
412	Return exactly one verdict for every id from 1 to ${input.entries.length}.`;
413	}

420	  reciting: boolean;

447	export type LineVerdict = "strong" | "partial" | "thin" | "skipped";

449	const LINE_VERDICTS: LineVerdict[] = ["strong", "partial", "thin", "skipped"];
450	
451	function toLineVerdict(value: unknown): LineVerdict {
452	  const v = String(value ?? "").toLowerCase() as LineVerdict;
453	  // Anything unrecognised is "thin" rather than "strong": a judge that garbles
454	  // the field must not be able to award a line she may never have spoken.
455	  return LINE_VERDICTS.includes(v) ? v : "thin";
456	}

461	/**
462	 * Pull the JSON out of whatever the model actually sent.
463	 *
464	 * Told not to use a code fence, models use one anyway, and some prepend a
465	 * sentence. Rather than trusting the instruction this finds the outermost
466	 * balanced object. A reply that is not parseable is an error and never a zero:
467	 * a grade of 0% and a grade we failed to read are different facts, and only one
468	 * of them is about her.
469	 */
470	export function extractJson(raw: string): unknown {
471	  const text = raw.trim().replace(/^```(?:json)?/i, "").replace(/```$/, "").trim();
472	  const start = text.indexOf("{");
473	  if (start === -1) throw new JudgeReplyError("no JSON object in the reply");
474	  let depth = 0;
475	  let inString = false;
476	  let escaped = false;
477	  for (let i = start; i < text.length; i++) {
478	    const c = text[i];
479	    if (inString) {
480	      if (escaped) escaped = false;
481	      else if (c === "\\") escaped = true;
482	      else if (c === '"') inString = false;
483	      continue;
484	    }
485	    if (c === '"') inString = true;
486	    else if (c === "{") depth++;
487	    else if (c === "}" && --depth === 0) {
488	      try {
489	        return JSON.parse(text.slice(start, i + 1));
490	      } catch (e) {
491	        throw new JudgeReplyError(`unparseable JSON: ${(e as Error).message}`);
492	      }
493	    }
494	  }
495	  throw new JudgeReplyError("JSON object never closed");
496	}

498	export function parseJudgeReply(raw: string, expectedIds: number[]): JudgeReply {
499	  const obj = extractJson(raw) as Record<string, unknown>;
500	  const rows = obj.verdicts;
501	  if (!Array.isArray(rows)) throw new JudgeReplyError("reply has no verdicts array");
502	
503	  const verdicts: Record<number, boolean> = {};
504	  for (const row of rows) {
505	    const r = row as Record<string, unknown>;
506	    const id = typeof r.id === "number" ? r.id : Number(r.id);
507	    if (!Number.isFinite(id)) continue;
508	    verdicts[id] = r.carried === true;
509	  }
510	  const missingIds = expectedIds.filter((id) => !(id in verdicts));
511	  const flag = (k: string) => obj[k] === true;
512	  const reason = (k: string) => (typeof obj[k] === "string" ? (obj[k] as string) : "");
513	
514	  const lineVerdicts: Record<number, { verdict: LineVerdict; note: string }> = {};
515	  if (Array.isArray(obj.lines)) {
516	    for (const row of obj.lines as Record<string, unknown>[]) {
517	      const n = Number(row?.n);
518	      if (!Number.isFinite(n)) continue;
519	      lineVerdicts[n] = {
520	        verdict: toLineVerdict(row.verdict),
521	        note: typeof row.note === "string" ? row.note : "",
522	      };
523	    }
524	  }
525	  const recallRow = obj.recall as Record<string, unknown> | undefined;
526	
527	  return {
528	    verdicts,
529	    reciting: flag("reciting"),
530	    recitingReason: reason("reciting_reason"),
531	    listing: flag("listing"),
532	    listingReason: reason("listing_reason"),
533	    // Absent is treated as "no colour" rather than as colour, so a judge that
534	    // forgets the field cannot silently award it.
535	    coloured: flag("coloured"),
536	    colourSpecific: flag("colour_specific"),
537	    // Absent is "no Read", for the same reason as colour: a judge that forgets
538	    // the field must not be able to award it, and a stimulus judged before The
539	    // Read was graded at all is honestly reported as not having one.
540	    readGiven: flag("read_given"),
541	    readMatches: flag("read_matches"),
542	    readReason: reason("read_reason"),
543	    missingIds,
544	    bigMisses: Array.isArray(obj.big_misses)
545	      ? (obj.big_misses as unknown[])
546	          .filter((m): m is string => typeof m === "string" && m.trim() !== "")
547	          .slice(0, 3)
548	      : [],
549	    lineVerdicts,
550	    recallVerdict: recallRow
551	      ? { verdict: toLineVerdict(recallRow.verdict), note: typeof recallRow.note === "string" ? recallRow.note : "" }
552	      : undefined,
553	  };
554	}

604	export function gradeStimulus(
605	  entries: JudgeEntry[],
606	  reply: JudgeReply,
607	  /** Her run cut into lines, when it could be. Feedback only, never scored. */
608	  lineSpans: { n: number; text: string; spoken: string; startMs?: number; endMs?: number }[] = [],
609	): StimulusGrade {
610	  const own = entries.filter((e) => !e.decoy);
611	  const carriedEntries = own.filter((e) => reply.verdicts[e.id] === true);
612	  const total = own.length;
613	  // Guard the empty stimulus rather than dividing by zero into NaN, which
614	  // renders as a blank band and looks like a rendering bug.
615	  const percent = total === 0 ? 0 : Math.round((carriedEntries.length / total) * 100);
616	
617	  const lines: LineGrade[] = lineSpans.map((span) => {
618	    const forLine = own.filter((e) => e.line === span.n);
619	    const judged = reply.lineVerdicts[span.n];
620	    return {
621	      n: span.n,
622	      text: span.text,
623	      spoken: span.spoken,
624	      startMs: span.startMs,
625	      endMs: span.endMs,
626	      // She said nothing here, so it is a skip whatever the judge called it.
627	      verdict: span.spoken.trim() === "" ? "skipped" : (judged?.verdict ?? "thin"),
628	      note: judged?.note ?? "",
629	      carried: forLine.filter((e) => reply.verdicts[e.id] === true).map((e) => e.text),
630	      dropped: forLine.filter((e) => reply.verdicts[e.id] !== true).map((e) => e.text),
631	    };
632	  });
633	
634	  return {
635	    carried: carriedEntries.length,
636	    total,
637	    percent,
638	    band: bandFor(percent),
639	    missed: own.filter((e) => reply.verdicts[e.id] !== true).map((e) => e.text),
640	    decoysCarried: entries.filter((e) => e.decoy && reply.verdicts[e.id] === true).map((e) => e.text),
641	    unjudged: own.filter((e) => reply.missingIds.includes(e.id)).map((e) => e.text),
642	    reciting: reply.reciting,
643	    listing: reply.listing,
644	    coloured: reply.coloured,
645	    colourSpecific: reply.colourSpecific,
646	    readGiven: reply.readGiven,
647	    // A Read that was never given cannot have matched. Enforced here rather
648	    // than trusted, so a judge answering both true cannot invent one.
649	    readMatches: reply.readGiven && reply.readMatches,
650	    readReason: reply.readReason,
651	    lines,
652	    recall: reply.recallVerdict,
653	    bigMisses: reply.bigMisses,
654	  };
655	
656	}

658	/**
659	 * Run `worker` over every item, at most `limit` of them in flight.
660	 *
661	 * A section is 22 stimuli and each one costs a judge call. Run end to end that
662	 * is 22 round trips in series, which on the trial run exceeded the edge
663	 * function's wall clock and returned 504 -- so the student's whole run produced
664	 * no Report Card, having already been recorded, uploaded and transcribed
665	 * correctly. Run at once it is one round trip's worth of waiting.
666	 *
667	 * Bounded rather than unbounded because the judge is a rate-limited API and a
668	 * section is not the only thing that might be grading; 429s at the provider
669	 * would trade one failure mode for another.
670	 *
671	 * Results come back in the order of `items`, not the order they finished. The
672	 * caller writes them into a Report Card the student reads top to bottom, and a
673	 * section whose stimuli arrive shuffled is worse than a slow one.
674	 *

carried, as one number per stimulus. It did not say what number is good, and the
obvious reading of a percentage is that 100 is the target.

That reading is measurably false. Joshua's own recordings are the drill done
correctly, and they are the standard the Details were calibrated against. Put
through `student_shaped.py`, which removes the verbatim reads a student never
speaks, **all 71 stimuli of the three built sections were scored Detail by
Detail** — a census, not a sample, of 1,294 judgements:

| | Coverage |
|---|---|
| Mean | 94.7% |
| Median | 95% |
| 10th percentile | 86% |
| Minimum | 68% |
| Maximum | 100% |
| Runs at 100% | 22 of 71 |

He reaches a clean sweep on fewer than a third of them, and the distribution has
a real left tail: two runs below 83%, and one at 68%.

The two lowest are both explained rather than mysterious. PT134.S3.Q16's
recording starts mid-sentence, so part of the stimulus was never spoken at all;
it measures the recording. PT134.S3.Q1 ends in a fill-in-the-blank conclusion
("it would be reasonable for organizations… to _______"), which he answers in
four words, so a whole chunk's Details go uncarried. Excluding those two, the
range is 79 to 100 with a median of 96.

He is not sloppy and the key is not wrong. The calibration method already
settled this: "his own recall drops details, and that is not a defect… his run
is not a ceiling on the key." What is new is the shape of the distribution and
what sits in the misses. Across the census they are, in order of frequency:
**a small specific** — an adjective, a place, a time, a material ("the water is
seawater", "the stalagmites are numerous", "the announcement was earlier
today"); **a quantifier or hedge** ("the devices would go in all cars", "it is
generally so", "this is stated with certainty"); and **a speaker role or
discourse marker** ("Tom is the first speaker", "a lawyer is speaking").

Those are the exact words the drill exists to train. Coverage is measuring the
right thing; the scale is what is wrong.

A second measurement bears on how the judgement is asked. Classifying all 1,294
Details by what they actually assert
(`system/scripts/activity-centre/classify_details.py`) splits them three ways,
not two:

| Kind | Count | Share | Example |
|---|---|---|---|
| content | 1,133 | 87.6% | "The commitment is long-standing." |
| structure | 137 | 10.6% | "This is the conclusion." · "This is a contrast." · "An archaeologist is speaking." |
| modality | 24 | 1.9% | "This is hedged as probable." · "This is an average." · "This is almost always so." |

A **structure** Detail is carried by how she says the stimulus back, not by which
words she uses. Joshua carries "This is a contrast." by saying "Glass is
different from steel, though"; he carries "This is the conclusion." with a "so".
A judge asked *did she say this?* marks both missed. A judge asked *is this
relationship present in her retelling?* marks both carried.

A **modality** Detail is neither a fact nor a relationship but the strength of a
claim, and it is the class his runs drop most.

The three-way split is itself the finding. A two-way content/structure cut looks
sufficient until it is run: "This is about Sweden." and "This is the conclusion."
share an opening and are opposites, and a classifier keying on that opening puts
a topic fact in with the discourse roles. 12.4% of every score turns on asking
the right question of the right kind.

## Decision

**Coverage is reported against a band calibrated on the standard, never as a
raw percentage against an implied 100.**

| Band | Coverage | What it means |
|---|---|---|
| At the standard | 86% and above | The run the drill is asking for |
| Nearly there | 72–85% | Holding the argument, losing the detail |
| Thin | 55–71% | The shape survived and the content did not |
| Lost it | below 55% | Read it again |

**Only the top boundary is evidenced, and it is the 10th percentile of the
census** — nine correct runs in ten clear it. It is deliberately not the minimum:
the minimum of any sample is the most fragile statistic available, and here it is
a stimulus whose recording is broken.

**The three lower cutoffs are provisional and are marked as such.** The corpus
contains only correct runs, so it can calibrate where good ends and nothing else.
Where "nearly there" stops being nearly and starts being thin is unknown until
student runs exist, and inventing precision there would be dressing a guess as a
measurement.

**Each kind is judged by its own question.** Details are classified `content`,
`structure` or `modality` at build time, and the judge is asked: for content,
whether she stated the fact; for structure, whether the relationship is present
in how she told it; for modality, whether her qualifier survived. The
classification lives with the build, so a section carries it and the grader
never has to guess.

**The classifier is a closed set plus a residue detector, not a heuristic.**
`structure` and `modality` are matched against authored phrasings that are
enumerated, and anything opening like a discourse role that falls through to
`content` is reported rather than silently accepted. On the three built sections
the closed set leaves 4 residue lines out of 1,294, and all four are correctly
content. A new section's residue is read before it ships; a growing residue
means the authoring vocabulary has drifted, which is worth knowing on its own.

**Numbers above the top band are not ranked.** 100% and 88% are the same
outcome. The Report Card says a run is at the standard and moves on to what she
missed; it does not put her in a race against an unreachable maximum, and it
does not congratulate a difference the measurement cannot support.

## Consequences

**ADR 0012's estimate of the grading job is corrected.** It records "roughly 92
Detail judgements per section". The three built sections carry **426, 419 and
449** Details. 92 is approximately the *chunk* count (80, 82, 87), which is what
the number was when Coverage was still conceived per chunk; ADR 0013 moved
Coverage to the stimulus and the estimate did not follow. The job is about five
times the recorded size. It stays about 25 model calls, because the Details of
one stimulus are judged together.

**Reciting and Listing become load-bearing, not decorative.** With the top band
starting at 86%, a student who recites reaches it trivially. ADR 0012 already
names both failures and puts them in the tips rather than the number. That
division only holds if the tips actually fire, so Reciting is graded in code
against the chunk text and cannot be skipped as a nice-to-have.

**A student can be at the standard and still be told what she lost.** The band
answers "was this run good"; the missed Details answer "what did you drop". They
are different questions and the Report Card shows both, which is what stops the
top band from reading as nothing left to learn.

**The floor rests on 71 runs and should eventually rest on more.** The corpus
supports 713, and the remaining 642 are stimuli from sections that are not built
yet. Re-running the census is the natural first use of the regression suite in
[0017](./0017-the-grader-hears-the-run-through-the-same-ear-as-the-standard.md),
and the cutoff moves by measurement rather than by taste when it does.

**A fill-in-the-blank stimulus needs its own handling and does not have it.**
PT134.S3.Q1 is the census minimum because its final chunk is a blank the speaker
completes in four words, and its Details describe a conclusion that is not on the
page. Every section will have a few. Nothing in this ADR fixes that, and a
student will hit the same floor on the same stimuli.

## Validated against a real model, 2026-09-02

The bands above were drawn from judging done by hand and by agent. The grader
does not use either. `scripts/grade-census.ts` ran the actual judge -- the real
prompt, `gemini-2.5-flash` at temperature 0 -- over all 71 census stimuli:

| | min | p10 | median | mean |
|---|---|---|---|---|
| Census (hand + agent) | 68 | **86** | 95 | 94.7 |
| Judge (gemini-2.5-flash) | 59 | **85** | 94 | 93.1 |

**The floor holds.** Judge p10 is 85 against a census p10 of 86: the two agree
within a point, which is validation rather than discrepancy. Mean delta is
**-1.6 points**, so the model is very slightly stricter than a person, and 58 of
71 land within 5 points. The floor stays at 86; moving it one point on this
evidence would claim a precision the measurement does not have.

**87% of correct runs land at the standard**, 11% at "nearly there", one at
"thin". At section level the mean is 93%, comfortably inside the top band, so a
correct run reads as correct; the spread is per stimulus.

**Nothing failed to parse.** 71 replies, zero unreadable, zero Details left
unjudged.

**The decoys caught something, which is the point.** 4 of 71 stimuli had the
judge credit a Detail belonging to a different stimulus -- one decoy of two,
each time. That is the failure this ADR's judging rule exists to prevent, it is
invisible in a Coverage number, and without decoys we would not know it happens
at a 5.6% rate. It is recorded per grade so a run carrying one can be treated as
suspect rather than reported as fact.

**Cost is not a consideration.** ~1,750 tokens per stimulus; ~124,000 for the
whole census; roughly 41,000 to grade one student's section.

## Alternatives considered

**Normalise each stimulus against Joshua's own Coverage on it, so his run is
100.** Rejected. It makes the scale depend on how well he happened to do that
day, and on the 22 stimuli where he scored 100 it leaves her no headroom while
on the 68% one it hands her 32 points. The calibration method is explicit that his run
is one sample and not a ceiling; a per-stimulus normaliser treats it as both.

**Show the raw percentage and put the target in the copy.** Offered and
rejected. A number and a caption disagreeing is a number winning: 88% next to
"this is a good run" reads as consolation.

**Drop the structural Details from the key so Coverage is content only.**
Rejected. They are 10.6% of the key and they are the argument's skeleton, which
is the thing The Recall exists to test. The fix is to ask the judge the right
question, not to stop asking.

**Weight Details by importance so a proper noun counts less than a conclusion.**
Rejected for now. It needs a per-Detail authored weight over 1,294 rows, and the
band already absorbs the variance a weighting would model.

## Amendment: a recital wore the top band anyway

Date: 2026-09-04

"Reciting and Listing become load-bearing, not decorative" was written about the
grader and only about the grader. It was true there: Reciting is graded in code,
it fired, and the run that recited was flagged.

It was not true on the card. In the 2026-09-03 trial, stimulus 3 was read out
verbatim during The Recall, was correctly flagged, and its row still read
**"At the standard, 20 of 20" in green**. The recital sentence lived inside the
expanded row, which is the half a student has to go looking for. The band is the
half she reads.

So this ADR said coverage reached by reciting is a failure while the interface
said it was the best possible result, on the same stimulus, at the same moment.

### Decision

A stimulus flagged Reciting does not wear a band. Its collapsed row says
**"Said back word for word"** in neutral type, with no success colour and no
success dot.

Deliberately not a fifth band and deliberately not red. A recital is not a worse
score -- it can carry every Detail, and that is the whole problem. The row is
saying that the number beside it did not come from memory, which is a statement
about the method rather than a mark against her.

The count stays. "20 of 20" is a true reading and suppressing it would hide
evidence rather than correct a claim; what changes is that nothing beside it
calls that a success.

### Consequences

**The band and the tip can no longer disagree.** They were two renderings of one
judgement and only one of them was reachable without a click.

**This depends on the Reciting threshold being right**, which it was not: see
[0022](./0022-reciting-is-a-share-not-a-streak.md)'s 2026-09-04 amendment, where
four of Joshua's own 274 model runs were flagging. Suppressing the band on a
false positive would have turned honest rows grey, so the threshold was fixed
first.

# 0017 — The grader hears the run through the same ear as the standard

Date: 2026-09-01
Status: accepted
Amended: 2026-09-04 (see "Amendment: the title was a claim the code did not honour")
Extends [0013](./0013-she-chunks-freely-and-the-app-does-not-track-it.md).

## Context

A finished section leaves two recordings of what she said, and they are not
equivalent.

The first is the audio: one unbroken file per section, `getUserMedia` into a
`MediaRecorder` started once on mount and stopped once at the end
(`useSectionRecorder.ts`), uploaded to `drill-recordings` at
`<student_id>/<assignment_id>.webm`. Nothing in the app reads it back.

The second is text: `useSectionTranscript.ts` runs the browser's
`SpeechRecognition` continuously through the section and slices it by the same
phase boundaries, and that slice is what lands in
`activity_item_responses.response_text` and `rrc.transcript_segments`, tagged
`transcript_source: "browser-speech"`.

The cheap move is to grade the text that is already there. Three things rule it
out.

`SpeechRecognition` is a Chrome interface. In Safari and Firefox it does not
exist, `said` is empty, and the writer stores `response_text: ""` with
`transcript_source: null` (it stored `null` until ADR 0027, and a null in a
NOT NULL column meant the row was never saved at all). The section still
records audio, still writes its row, and produces no text to grade — a silent,
browser-dependent hole rather than an error.

It carries no usable timing. Dead air is a graded criterion and it is only
meaningful inside The Recall, where silence is unambiguously a failure rather
than a silent read. Measuring it needs word-level timestamps.

And it is a different ear from the one that read the standard. The 1,294
Details were authored and calibrated against Joshua's own runs, and those runs
were re-transcribed on Deepgram Nova-3 on 2026-09-01 precisely because the local
Whisper model paraphrased away the hesitations and false starts that are the
content. Grading a student on a weaker transcript than the reference does not
make the grader lenient; it makes it wrong in one direction, dropping her words
before any judgement is made and charging the loss to her Coverage.

## Decision

**The graded transcript is produced server-side by Deepgram Nova-3 from the
uploaded recording.** The same engine that read the standard reads the run.

**The browser transcript stays, and is never graded.** It costs nothing, it is
the only text that exists if the upload fails, and it is useful as a diagnostic
when a Coverage score is disputed. It is stored as what it is, and the grade
records which transcript it was computed from.

**Segmentation is not an audio problem.** `rrc.audio_segments` already carries
`{slug, order, phase, startMs, endMs}` for every `working` and `recalling`
window, written from the two presses of the Space key. Deepgram's word
timestamps are cut against those offsets. Nothing has to infer stimulus
boundaries from the audio, which is the whole reason ADR 0013's second press
exists.

## Consequences

**One new secret.** `DEEPGRAM_API_KEY` in the edge function environment. It is
the first ASR dependency the app has had; every LLM call still goes through
`gemini-proxy`, and this does not change that.

**Grading is asynchronous and the Report Card has a pending state.** A 25-minute
section is one transcription plus roughly 25 judgement calls, one per stimulus.
It does not complete inside the request that finishes the section, and it must
not be tied to the tab staying open.

**Cost is not a constraint.** The whole 714-file corpus transcribed for $6.62.
A section is about $0.11.
