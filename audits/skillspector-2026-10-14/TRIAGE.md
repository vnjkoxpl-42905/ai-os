# Triage of the 2026-10-14 SkillSpector scan

Written by hand after reading the flagged lines. `SUMMARY.md` is generated by `summarize.py`; this file is not.

## How the scan was run

- SkillSpector 2.12.0, static mode only: `skillspector scan --no-llm`. File contents stayed on this machine. The SC4 check sends declared dependency names and versions to api.osv.dev.
- `skillspector scan --recursive` stops after a 32-skill budget, which left 82 of 114 vault skills unscanned. That partial run is kept in `first-attempt-recursive/`. `scan_each.sh` then scanned each skill folder on its own: 114 in `.claude/skills` and 279 in `~/.claude/skills`. Three home entries have no `SKILL.md` and were skipped: `grill-me.broken-symlink.bak`, `synced` and `to-prd` (a broken link).
- Result: 393 reports. 37 CRITICAL, 12 HIGH, 35 MEDIUM, 309 LOW (counted per root, so a skill in both roots counts twice).
- Coverage is "partial" for most flagged skills because of the scanner's per-file size and time limits, not because of an error.

## What the flags actually are

No finding read so far shows malicious behavior. The HIGH and CRITICAL scores come mostly from word patterns in documentation:

| Rule | Count (HIGH+) | What it matched |
|---|---|---|
| P2 prompt injection | 217 | Imperative wording in instructions |
| AE1 analysis evasion | 151 | Files the scanner could not fully read (size or time limit) |
| PE3 credential access | 79 | Scripts that read an API key from the environment or `.env` |
| YR4, P1 | 40 | Security warnings that quote "ignore previous instructions" (for example `browser-testing-with-devtools` SKILL.md:77, `source-driven-development` SKILL.md:110) and test cassettes containing the word "tools" |
| E2 env harvesting | 6 | `os.environ.copy()` used to launch LibreOffice (`docx`, `pptx`, `xlsx` from Anthropic) |
| YR1 info stealer | 5 | The word "cookies" in docs (`supabase`, `browser-testing-with-devtools`) |
