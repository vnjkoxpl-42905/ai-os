# References, a design loop and editable website controls

**Source:** Build $10,000 Website with GPT-6 ASTRA In 12 Minutes. Author: Jack (surname unknown in clip). [Original video](https://www.youtube.com/watch?v=xqCdvm-YoIM). Publication and capture dates unknown. Ingested 2026-10-24.

**Evidence:** [preserved complete clip](../../raw/sources/clips/astra-website-design-loop-jack/source.md), [provenance and hash](../../raw/sources/clips/astra-website-design-loop-jack/PROVENANCE.md). Status: captured and text-compiled, not independently tested.

## What the source says

- At 0:53–2:07 the narrator starts from reference sites and a mood board. The description lists mobile, animation, navbar, CTA and component galleries. Names differ between the description and automatic transcript, so these are leads to check, not verified URLs.

- At 2:07–5:25 he recommends a Design Loop skill, design references and image/video generation through a Higgsfield plugin. He explicitly could not validate which native image model his Codex attempt used (3:52).

- At 5:25–7:35 he describes an iterative multi-agent design loop and shows websites at several screen sizes. His satisfaction with the output is subjective, not a controlled comparison.

- At 7:35–12:19 he proposes a website operating system: device previews, palette and typography controls, an asset inventory, direct copy edits, image/video regeneration, a prose-review tool and editable SEO metadata. The intent is to avoid rebuilding a whole page for every minor edit.

- At 8:45 he calls finding a specific replacement component on 21st.dev UI sniping. At 7:08 he discusses converting still imagery into short looping video; neither is a requirement to animate every dashboard element.

## Application here, separated from source claims

The useful transfer is a reusable visual reference library and cheap, narrowly scoped refinement controls. For the student dashboard, direct task access and legible content remain the goal; an asset generator or SEO editor is a separate authoring feature.

## Actionable proposals

- Maintain categorized visual references with explicit reasons for selection (overlaps the requested design hub).
- Evaluate the promoted Design Loop skill before installation; its linked guide was not retrieved in this ingest.
- Evaluate lightweight palette/type/spacing controls and replayable previews on a prototype rather than rebuilding for each adjustment.
- Evaluate a small editable content/asset/metadata panel only if repeated maintenance justifies it.
- Inspect plugin/model identity and generation cost before adopting Higgsfield asset generation; do not assume source claims prove access.
- Compare any promoted prose checker with the existing humanizer instead of installing a duplicate.
