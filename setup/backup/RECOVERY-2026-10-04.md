# Restore the 2026-10-04 laptop recovery

Use runtime-final.7z.001 and all runtime-final numbered volumes. The earlier runtime archive is superseded because its scan overlapped the final live SQLite capture. runtime-final was built after the consistent snapshot settled and includes additional global tool settings.

These private archives include passwords, local credentials, student records, and personal files. Keep them in your private Google Drive. The accompanying SHA256SUMS.txt and archive test logs establish the saved archive contents. A cloud upload still needs a separate verification.

1. On the new Windows computer install 7-Zip, Git, Node.js LTS, Python, Codex desktop, Claude Code, Obsidian, Google Drive for Desktop, and any other apps you use. Sign in to Google Drive using contact@aspiringattorneys.com.
2. Download ALL numbered volumes for each category into the same folder. Open the .7z.001 file with 7-Zip and extract into a NEW empty recovery folder. Keep every volume; later volumes are required.
3. runtime contains user-profile directories such as .codex, .claude, .agents, .config and dotfiles. second-brain contains dev\ai-os. development contains other dev folders, including ai-os-projects. app-data contains AppData directories. Combine these under the new user profile only after backing up any existing target files. No automatic restore is run and nothing is deleted.
4. Prefer the same Windows username (Joshu), keeping C:\Users\Joshu\dev\ai-os and C:\Users\Joshu\dev\ai-os-projects. If the username differs, restore into the new profile then repair old absolute paths in Codex/Claude settings and Git worktree metadata. Do not blindly replace text in databases. Run git worktree repair in each main repository with its restored worktree paths. Codex managed worktrees live inside .codex\worktrees, and must remain with their main repositories.
5. The regular runtime/app-data SQLite files were captured through SQLite's backup API and checked with PRAGMA quick_check. sqlite-live-raw is forensic evidence of the original live database plus WAL files, and must not be copied over the consistent snapshots. The raw files are separately retained; source applications were open during backup.
6. Reinstall dependencies in each project using its lockfile and package manager. node_modules, Python virtual environments, build caches, and __pycache__ were omitted. Project source, Git history, uncommitted work, raw sources, .env, and local AI configuration were included. Symbolic links/junctions are not traversed. Inspect logs and ISSUES.txt for any inaccessible or failed files.
7. Sign in again where requested. Windows keyring/DPAPI secrets, browser cookies, Store app settings, OAuth sessions, and credentials bound to this computer may not work on a new computer. Reinstall apps instead of restoring their binaries. For Codex Store package user data, consult the saved AppData category; copying it requires the app closed and may require matching the newly installed package directory.
8. Verify student folders, raw sources, .env, recent Codex and Claude chats, automemory, project branches, uncommitted work and worktrees before returning or wiping the old laptop. The current Codex chat may still be writing during capture and may require a final capture after work ends.

This is a file/data recovery backup, not a full bootable Windows image. Programs, licenses, OS settings and machine-bound secrets require installation or sign-in. See inventory and exclusions for personal-file coverage.

## Restore on a Mac

1. Install Codex desktop for Mac, Claude Code, Obsidian, Git, Node.js LTS, Python, Google Drive for Desktop and 7-Zip (Homebrew package sevenzip). Sign into the same private Google Drive account and download every numbered archive volume.
2. Extract each category into a NEW empty folder with 7-Zip. With Homebrew's 7zz command, use `7zz x /path/to/runtime-final.7z.001 -o/path/to/empty-recovery-folder`. Extract second-brain, development, personal-files and other categories the same way. Keep sqlite-live-raw as evidence.
3. With Codex and Claude closed, first back up any existing Mac dotdirectories. Copy runtime/.codex, runtime/.claude, runtime/.agents and other portable settings to your Mac home directory. Copy second-brain/dev/ai-os to ~/dev/ai-os, and development/dev/ai-os-projects plus the other project directories to ~/dev/. Copy Documents/Desktop/Downloads from personal-files where desired after checking for existing files. Do not blindly overwrite a populated Mac home directory.
4. Keep Windows app-data separately. Do not copy AppData into macOS Library and expect Windows apps to work. Install Mac apps and import their settings using the apps' own import features where available. Superwhisper recordings, modes and vocabulary remain useful evidence; Windows database/settings import into the Mac app is unverified.
5. Windows absolute paths such as C:\Users\Joshu must be repaired in config files and Git worktree registrations. Claude project-history directory names encode the original Windows path. Rename only after keeping an untouched copy and confirming the new folder's encoded Mac path. Avoid bulk text replacements in databases. Codex chat/history recognition across Windows-to-Mac and different app/database versions is unverified; preserve the complete backups even if the new app does not immediately show all restored chats.
6. Reinstall plugins and tool runtimes for macOS. Windows binaries in backed-up plugin caches cannot run on macOS. Reinstall each project's Node/Python dependencies from its lockfiles. Sign into Codex, Claude, Google Workspace, GitHub, and other services again as needed. Repair Git worktrees without pruning saved registrations, using each main repository and the restored paths.
7. Verify the vault, .env, student records, raw material, recent AI chats, automemory, each project's uncommitted work and branch history before relying on the new Mac.

The older restore.ps1/restore.sh in the historical Drive backup are not authoritative for these new recovery archives. This guide preserves the sibling project layout and both platform choices.

## Known exceptions

The captured Superwhisper database failed SQLite quick_check with repeated-page errors. The original was not altered. A raw copy of its database and WAL, recordings, settings and modes are retained. Two embedded browser-cache databases were locked during capture. Superwhisper model binaries were omitted (re-download them). Check APP-EXTRAS-ISSUES.txt and SQLite reports for exact paths. The original runtime capture was interrupted to resolve live SQLite backup starvation; the retry captured all seven Codex databases with quick_check success and runtime-final is authoritative. OneDrive Personal Vault contents were not verified; a shortcut is not evidence that vault contents were backed up.
