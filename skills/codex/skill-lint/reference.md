# Skill lint procedures

## Discover and classify

Resolve the current project and actual runtime roots. Inspect immediate skill folders for `SKILL.md`, then read metadata before full instructions. The loaded package is an activation; a catalog is storage. Record both when a sharing policy names them. Missing `SKILL.md` does not authorize deleting a folder: it may contain assets, scripts, archives, or a project fork.

For each suspected defect, record the exact source file, expected base directory, target or dependency, observed result, root cause, and proposed fix. Distinguish concrete paths from examples, placeholders, globs, remote-host paths, and optional resources. A tool unavailable in this session may be an alternative workflow or verification gap rather than a nonexistent dependency.

## Verify safely

Use available file/search tools or `rg`, Python, and the host shell; do not assume Glob/Read/Bash tool names. On Windows use PowerShell-native path checks and commands. Check installed command help/version before relying on flags. Inspect unknown scripts for side effects before executing them. Use synthetic fixtures for scripts that otherwise consume history or perform external actions.

For duplicate copies, compare purpose, declared identity/aliases, frontmatter, supporting resources, and documented runtime adaptations. Preserve an independent implementation until its relationship is established. A transformed runtime copy need not be byte-identical to its source.

## Manage local copies

Origin metadata such as `.skill-origin.json` is useful only when it actually exists; do not fabricate origins, commit counts, or precedence. Show a diff before rollback or destructive replacement. Follow the repository's catalog/activation policy. Record the exact changed copies and verify the resources they reference after synchronization. Do not modify unrelated runtime configuration or operating manuals as an incidental repair.

## Feedback and delivery

Prepare a concise local report or draft containing the defect, evidence, impact, and proposed remedy. Remove secrets and unnecessary private information. A request to diagnose, optimize, or fix a skill does not authorize a GitHub post, gist, PR, email, Slack message, upvote, resolution comment, or thread lock.

For an explicitly authorized external action, verify the named destination and available CLI/connector, show the concrete content when needed, and honor existing approval in the conversation without asking again. Report the actual result and link it. Do not assume a particular Discussion thread or channel exists.

## Output

Report inspected roots and skill count, confirmed fixes, preserved intentional differences, and unresolved verification gaps. Separate metadata/link checks from execution tests. State whether supporting files were preserved and whether any external action occurred.
