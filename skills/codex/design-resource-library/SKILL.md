# Design resource library

Use [the resource map](references/resources.md) to select relevant resources, not to load every tool or impose one aesthetic. The owner's current creative brief takes precedence over example styles, old reference screens and optional skill presets.

1. Check the actual workspace, current skill/tool availability and existing implementation. Reuse installed GSAP, React Bits, shadcn, icons and the existing voice guidance when appropriate.
2. Research with working Tavily/Firecrawl tools or a browser. Component metadata is not visual evidence: open suitable previews or screenshots. Distinguish public access, authenticated browser sessions and API entitlement.
3. Fetch current component source and inspect its props, framework, dependencies and licence. Use the existing `react-bits` helper for that library. Canvas UI supports `@canvas-ui` through shadcn. Do not install unused effect packs in advance.
4. Let the model choose typography, composition and references for the requested work. Fonts and icon sets have individual licences; retain required notices with selected assets.
5. Iterate through the rendered result. Headless screenshots are valid visual checkpoints when actually inspected; motion needs natural playback or a recording, not a forced final timeline. Verify actual viewport width and report real layout errors.

For AI OS homepage work, the current setup and resume pointers are in `../../../research/2026-10-23-dashboard-design-readiness.md`. Recheck operational state rather than treating this dated report as permanent truth.
