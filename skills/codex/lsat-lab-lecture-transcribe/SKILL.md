# LSAT Lab lectures for live teaching

Joshua has stated that, as an LSAT Lab tutor, he is authorized to use and adapt the selected lectures. Capture only the selected lecture(s); this does not authorize library-wide collection or publishing. This skill handles video lectures; `lsat-lab-transcribe` handles written PrepTest explanations.

## Capture once, then assemble

1. Read the repository instructions and `wiki/teaching-voice.md`. Use the current approved browser skill and its documented tools. Reuse the selected LSAT Lab tab. In Codex, use CUA with the in-app browser; in another runtime, use its approved browser surface. Do not copy outdated CDP/Playwright instructions from older skills or guess media/caption URLs.
2. Verify the live title, instructor, lecture date, video ID, duration, and URL. Read `corpus/lectures/index.md` and follow its section/topic/level indices before creating anything. Home: `corpus/lectures/<logical-reasoning-or-reading-comprehension>/<topic>/<core-or-advanced>/<lecture-date>-<videoid>/`. Record section, topic, level, platform, and concept tags as metadata. Topics can be question types, families, or reasoning skills; use one canonical home with cross-links for overlap. Core/advanced is the lecture's filing level, not a claim about every worked question. If the lecture date is unavailable, use `undated-<videoid>` and record that uncertainty.
3. Prefer the native full transcript/caption export or supplied local subtitles. For the authorized fast capture route, read [capture.md](references/capture.md): the local helper retrieves captions/video from the player URL actually observed in the selected page, then extracts exact-time frames locally. Do not guess media URLs or read browser cookies. A virtualized Transcript List may expose only a few visible cues: scroll through every chunk, deduplicate by cue index/timestamp, confirm the last cue, and reconcile the entire cue timeline with the verified runtime. Check unexplained middle gaps as well as opening/ending against playback. Preserve the original extraction and provenance/hash under `raw/sources/lsat-lab-lectures/<videoid>/`, then make a hash-verified archive copy. Note whether captions are automated or authored. If no captions exist, use an authorized audio transcription route and verify uncertain words against the video. Never replace missing source with a guessed lecture. Report incomplete access precisely.
4. Derive a chronological outline from the transcript, then seek to visual milestones. Capture the introductory concept board before the first question; each question's readable stimulus, stem, and all answer choices; and important intermediate/final board states showing the reasoning. Multiple frames are appropriate if the whole question cannot fit. Capture visuals where they explain a teaching step, not on an arbitrary every-N-seconds schedule. Verify the settled player timestamp and image readability after every seek.
5. Checkpoint `progress.json` after each completed segment/question: selected URL, duration, transcript status, verified through-time, completed question IDs, next seek time, missing captures, and blockers. Resume from this checkpoint instead of extracting everything again.
6. Create the adapted script in short, readable paragraphs. Keep nearly all substantive wording, examples, distinctions, wrong-answer reasoning, transitions, and teaching sequence. Remove student names, attendance, greetings, technical interruptions, repetition caused by interruption, and logistics. Replace name-based references with a natural direct explanation. Preserve specific question reasoning when it teaches something useful; do not collapse it into a generic concept summary. Mark uncertain words and missing material explicitly. Keep the untouched source transcript separate.
7. Map each script segment to its source time interval and transcript line interval, concept tags, question ID where applicable, and exact screenshot filenames/times. Put unspoken visual cues outside spoken text. The user should be able to read a paragraph, show the adjacent board, and continue without reconstructing the lesson. Include pause/check-for-understanding cues when supported by the source.
8. Write `teaching-brief.md` before the reading script: scope, prerequisites, key concepts, ordered worked questions and board cues, common mistakes, explicit source corrections, and a practical teaching flow. This is unspoken preparation, not a student-specific dossier. Put its text in manifest `teaching_brief`. Use [the manifest contract](references/manifest.md) and `scripts/package_lecture.py` to generate the brief, `teleprompter.md`, self-contained `teleprompter.html`, `timeline.json`, `coverage.md`, `PROVENANCE.md`, and `SHA256SUMS`. The helper packages local captures only. It does not obtain captions or screenshots, judge logical correctness, or certify completeness. Preserve initial `transcript.md` and source screenshots unchanged; a later correction needs explicit provenance, not silent overwriting.
9. Review coverage against the entire source: all key teaching points, concept-board explanation, every worked question and substantive answer elimination, and conclusion. Record removed chatter and unresolved gaps. Check screenshot legibility and the script/image/time mapping. Open the HTML and test navigation, start/pause, speed, manual reading, and keyboard controls. Record actual checks; a successful helper run alone is not content verification.
10. Maintain `index.md` at every level: archive root, LR/RC section, topic, core/advanced, and individual lecture. Both level and individual-lecture indices list every worked question in presentation order with verified PT/section/question identifiers, source start/end times, reasoning tags, and script links. Distinguish introductory scanning examples from full worked questions, and preserve a different question type inside a mixed lecture. Register overlap through tags/cross-links instead of duplicate source copies. Append the meaningful system change to `wiki/log.md` following local routing. Report paths, source/caption confidence, questions and boards captured, and gaps. Never say complete when material or verification is missing. Do not send, post, or assign from this skill.

## Read-aloud deliverable

The default `teleprompter.html` is a private teacher cue sheet, one teaching moment at a time. Use short SAY chunks of roughly 40-80 spoken words, clear exact ASK wording, separate WAIT instructions, hidden EXPECTED RESPONSE, and copyable plain-ASCII BOARD content. Show each complete QUESTION's stimulus, stem, and five choices, with its original frame available to enlarge. Copy-question text must exclude answers and teacher notes. Put a suggested editable 120-second work timer before each question's walkthrough; identify this as teacher pacing, not a claimed source timing. Start/Pause/Reset never advances automatically; the teacher continues when ready. Keep the related question or board alongside its Socratic prompts.

Prepare sibling `lesson-steps.json` using [the contract](references/manifest.md). Preserve every substantive script passage across SAY steps, allowing only tracked voice substitutions. The helper verifies this coverage. It renders Previous/Next, section selection, step progress, copy buttons, optional text-size settings, and clipboard-selection fallback. The brief is closed by default and opens separately. Any optional SAY-only automatic pacing starts disabled and stops at every ASK, WAIT, BOARD, or QUESTION. The full continuous lecture remains in `teleprompter.md` and `continuous-script.html`; do not lose teaching detail to shorten the visible cards. This UI is for Joshua to read privately, not a student presentation page.

## Retrieve an existing lecture

For "use this lecture" or retrieval by topic, concept tag, or Core/Advanced level, follow the shared archive indices, open its teaching brief first, then its teleprompter. Root concept routing maps natural phrases such as applying facts to rules and linking rules to tagged lecture preparation. Each domain/topic/level/lecture index carries frontmatter section, topic/topic_type where relevant, difficulty where relevant, human aliases, and tags reflecting actual filed content. This library is wholly separate from student records. Do not file a lecture in, link it into, or modify a student's folder unless Joshua separately requests student-specific work.
